# لاسلكي (Lasilki) — تطبيق تكلّم مباشر شبيه بـ Zello 📻

تطبيق "اضغط للتحدث" (Push‑to‑Talk) يحوّل هاتف أندرويد إلى جهاز لاسلكي (ووكي‑توكي):
تضغط الزر فتُبثّ صوتك **مباشرةً ولحظياً** لكل من في القناة، وتسمع الآخرين أثناء تحدّثهم — تماماً كاللاسلكي الحقيقي.

## المميزات

- 🎙️ **بثّ صوتي مباشر (لحظي)** — صوت PCM يُلتقط ويُبثّ ويُشغّل أثناء الكلام، وليس بعد انتهائه.
- 🔒 **تسجيل دخول / إنشاء حساب** (كلمات مرور مشفّرة بـ scrypt + رموز جلسة).
- 📡 **عدة قنوات/مجموعات** — إنشاء قنوات والانضمام إليها.
- 👥 **قائمة المتصلين الآن** لكل قناة (حضور لحظي).
- 🗂️ **سجل الرسائل الصوتية** — كل إرسال يُحفظ كملف صوتي ويمكن إعادة الاستماع إليه.
- 🚦 **تحكّم في الإرسال (Floor control)** — متحدّث واحد في كل مرة مثل اللاسلكي الحقيقي ("القناة مشغولة").
- 🔔 **إشعار دائم + خدمة خلفية** — يبقى الاتصال يعمل والإشعار يُظهر من يتحدث الآن.

## بنية المشروع

```
walkie/
├── server/                 سيرفر Node.js (بدون أي مكتبة تحتاج بناء)
│   ├── server.js           REST + WebSocket (بثّ الصوت + الحضور + التحكم)
│   ├── db.js               قاعدة بيانات node:sqlite المدمجة
│   ├── auth.js             تشفير كلمات المرور + الرموز
│   ├── wav.js              بناء ملفات WAV من بيانات PCM للسجل
│   ├── test-client.mjs     اختبار محادثة بين مستخدمَين
│   └── uploads/            ملفات الصوت المحفوظة (السجل)
└── Lasilki/                تطبيق React Native (Android)
    ├── src/
    │   ├── api.ts          طلبات REST + إدارة الجلسة
    │   ├── ws.ts           اتصال WebSocket + إعادة اتصال
    │   ├── audio.ts        التقاط الصوت + تشغيله المباشر
    │   ├── service.ts      خدمة الخلفية والإشعارات
    │   └── screens/        شاشات الدخول/القنوات/القناة
    └── android/.../com/lasilki/
        ├── AudioStreamPlayerModule.kt   تشغيل PCM مباشر عبر AudioTrack
        ├── RadioForegroundService.kt    خدمة الخلفية + الإشعار
        └── RadioServiceModule.kt        تحكّم JS بالخدمة
```

### كيف يعمل الصوت المباشر؟
1. عند الضغط على الزر: `react-native-audio-record` يلتقط الصوت كدفعات **PCM16 (16kHz mono)** مُرمّزة Base64.
2. كل دفعة تُرسل فوراً عبر **WebSocket** إلى السيرفر.
3. السيرفر يُعيد بثّها لحظياً لبقية أعضاء القناة، ويجمعها لحفظها في السجل (WAV) عند انتهاء الإرسال.
4. على أجهزة المستمعين، الوحدة الأصلية **AudioStreamPlayer** تكتب الدفعات إلى `AudioTrack` في وضع البثّ فتُسمع مباشرة.

## 1) تشغيل السيرفر

> يتطلب Node.js 22+ (يستخدم `node:sqlite` المدمجة). لديك Node 25 — ممتاز.

```bash
cd walkie/server
npm install
npm start
```

سيظهر:
```
✅ سيرفر لاسلكي يعمل على المنفذ 4000
```

للتأكد من عمل كل شيء (تسجيل + دخول + بثّ صوتي + سجل):
```bash
npm run test-client
```

### معرفة عنوان جهازك على الشبكة (للأجهزة الحقيقية)
```powershell
ipconfig   # ابحث عن IPv4 مثل 192.168.1.10
```
سيكون عنوان السيرفر: `http://192.168.1.10:4000`

---

## 2) تشغيل التطبيق على أندرويد

### أ) على المحاكي (الأسرع للتجربة)
عنوان السيرفر الافتراضي `http://10.0.2.2:4000` يشير تلقائياً إلى السيرفر على جهازك.

```bash
cd walkie/Lasilki
npx react-native run-android
```

### ب) على جهاز حقيقي
1. وصّل الجهاز عبر USB (مع تفعيل وضع المطوّر) أو تأكّد أنه على نفس شبكة الواي‑فاي.
2. في شاشة الدخول، غيّر **عنوان السيرفر** إلى `http://<IP-جهازك>:4000`.
3. ثبّت التطبيق:
```bash
npx react-native run-android
```

### جرّبه مثل اللاسلكي 🎙️
- افتح التطبيق على **جهازين** (أو محاكي + جهاز)، سجّل حسابين مختلفين.
- ادخل نفس القناة (قناة «عام» موجودة افتراضياً).
- اضغط مع الاستمرار على الزر الكبير في جهاز وتكلّم — ستسمع صوتك مباشرة على الجهاز الآخر.

## 3) بناء ملف APK للتثبيت

```bash
cd walkie/Lasilki/android
./gradlew.bat assembleRelease     # على ويندوز
```
الناتج:
```
Lasilki/android/app/build/outputs/apk/release/app-release.apk
```
انسخه إلى الهاتف وثبّته. (هذا الإصدار موقّع بمفتاح التطوير للتجربة — لمتجر Google يلزم مفتاح إنتاج، انظر الأسفل.)

> **مهم:** الـ APK المبني يحتاج سيرفراً يمكنه الوصول إليه. للاستخدام خارج الشبكة المحلية، انشر السيرفر (انظر القسم التالي) وضع رابطه في شاشة الدخول.

---

## 4) نشر السيرفر (للعمل عبر الإنترنت)

السيرفر يعمل على أي استضافة Node. مثال **Railway**:
1. ارفع مجلد `server/` كمستودع، أو اربط Railway به.
2. أمر التشغيل: `npm start` (المنفذ يُقرأ من `process.env.PORT` تلقائياً).
3. لإبقاء السجل وقاعدة البيانات بعد إعادة التشغيل: أضف Volume واجعل مساره يحوي `lasilki.db` و`uploads/`.
4. استخدم رابط الاستضافة في التطبيق، مثل: `https://your-app.up.railway.app`
   (WebSocket يعمل تلقائياً عبر `wss://`).

## 5) إعداد إشعارات FCM (للعمل والتطبيق مغلق)

يحتاج هذا الجزء مشروع Firebase مجاني (مرة واحدة):

**أ) في وحدة تحكّم Firebase (console.firebase.google.com):**
1. أنشئ مشروعاً جديداً (أي اسم).
2. أضف تطبيق Android باسم الحزمة بالضبط: `com.lasilki`
3. نزّل ملف `google-services.json` وضعه في:
   `Lasilki/android/app/google-services.json`
4. من ⚙️ Project Settings → Service Accounts → **Generate new private key** → احفظ الملف.

**ب) للسيرفر (لكي يُرسل الإشعارات):** اختر إحدى الطريقتين:
- **محلياً:** ضع ملف المفتاح باسم `server/service-account.json`
- **على Railway (موصى به):** أضف متغيّر بيئة `FIREBASE_SERVICE_ACCOUNT` وقيمته **محتوى ملف المفتاح كاملاً** (JSON في سطر واحد).

**ج) أعد بناء التطبيق** بعد وضع `google-services.json` (انظر القسم 3).

> بدون هذه الإعدادات يعمل التطبيق بالكامل، لكن إشعارات «التطبيق مغلق تماماً» فقط تكون معطّلة (يبقى العمل في الخلفية وعند قفل الشاشة فعّالاً).

## ملاحظات تقنية ومحدوديات

- **الصوت:** PCM16 أحادي 16kHz — متوازن بين الوضوح وحجم البيانات (~32KB/ث). يطابق `wav.js` في السيرفر و`AUDIO` في التطبيق.
- **الخلفية:** خدمة foreground تُبقي الاتصال والصوت يعملان عند تصغير التطبيق أو إطفاء الشاشة، مع إشعار دائم يوضّح من يتحدث.
- **الإشعار حين يكون التطبيق مغلقاً تماماً:** مدعوم عبر Firebase Cloud Messaging (FCM) — انظر القسم «5) إعداد إشعارات FCM». عند بدء أحدهم الإرسال، يصل إشعار لكل عضو غير متصل حالياً، وبالضغط عليه يُفتح التطبيق على القناة مباشرة للاستماع. (التشغيل التلقائي الفوري للصوت والتطبيق مقتول غير مضمون على كل الأجهزة بسبب قيود أندرويد على الخلفية.)
- **HTTP غير المشفّر:** مُفعّل (`usesCleartextTraffic`) للتجربة المحلية. عند النشر استخدم `https/wss` فقط.

## مفتاح التوقيع للإنتاج (Google Play)
في `Lasilki/android/app/build.gradle` ضمن `signingConfigs`، أنشئ إعداداً جديداً بمفتاحك بدل مفتاح التطوير، ثم اربطه بـ `release`. أنشئ المفتاح بـ:
```bash
keytool -genkeypair -v -keystore lasilki.keystore -alias lasilki -keyalg RSA -keysize 2048 -validity 10000
```
